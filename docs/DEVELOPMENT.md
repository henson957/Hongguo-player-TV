# 开发与构建

[返回项目首页](../README.md)

以下内容记录实现细节和各候选版本的检查范围。

## 官网公开播放地址

App 线路和旧网页字段都没有可用地址时，读取官网为本集明确发布的公开 MP4。
校验剧集编号、分集编号、域名和清晰度，网页取址仍在整体超时预算内。
抽查五部剧的第 1 集均公布了 360P 地址，响应头返回 HTTP 200 和 video/mp4。
《持械入宋：第一季》第 2 集未公布地址，需要通过 App 播放接口取址。

## App 播放请求与 Android 9 榜单

推荐和排行榜改用兼容旧版 Android 电视的 DOM 查询和数字解析。榜单首页直接访问官网的标准地址。
App 播放请求补齐 Argus 和 Ladon，按实际发送的 query、请求体和匿名注册身份计算签名。
播放请求移除账号 Medusa，保留账号请求的原签名。失败时优先显示 App 取址错误。
使用公开固定向量离线核对请求签名。真实播放仍需电视验收。

## 创作者合集

普通网页详情返回 404 时也查询同一作品的合集目录。创作者合集按目录顺序列出真实分集，
播放时读取对应创作者视频的官方分享页。合集编号保持不变，原收藏可直接打开。
用公开目录核对《我的妹妹不可爱》的 10 集，并检查第 1 和第 10 集的分享页元数据。
没有下载视频或验证电视端的实际播放。

## 收藏与历史的详情回退

网页详情暂不可用时，使用同一个剧集编号查询 App 的分集列表。校验返回剧集和分集编号后才开放选集，
切换账号会清除详情缓存。此次构建按原约定检查编译、离线界面及 APK 封装，真实分集由电视端验收。

## 兼容片源与 404 回退

逐一检查批量、单集和其他已知播放线路返回的片源。批量模型只有不支持的编码或无法解析的密钥时，
继续查询所选分集的单集模型和兼容媒体配置。备用解析地址逐个尝试，单个地址返回 404 后可继续回退。
错误提示区分播放接口与网页播放页，并在确有地址或密钥错误时显示数量。

## 首次取址和换剧取址恢复

修正取址失败一次就直接提示重试的问题。首次播放最多执行三轮取址（两次自动重试），
下一集预取最多两轮；每轮重新读取本集信息，分别限制单轮和整个过程的时间，
前台取址总预算 20 秒，后台预取总预算 10 秒。成功就立即结束，不等待剩余轮次。
取址仍遵守原有的最高可播放清晰度选择，批量返回的后续分集继续共用缓存。

播放专用的临时注册身份现在保留在当前会话内，换剧时继续使用，避免每次回到旧身份。
播放注册不再排在搜索注册后面耗尽首次取址时间；并发播放注册会合并等待，
等待期间可取消，注册失败不会占用成功注册的 30 秒冷却时间。
账号切换和离开页面会停止旧请求；HTTP 429 直接提示限流，不自动换身份或继续重试。
网站缺少播放信息时不再覆盖已经取得的真实格式错误。
自动衔接仍在原播放器队列内进行，正常换集不主动弹出进度条；不生成离线视频文件。

## Android 9 搜索初始化闪退修正

rc5 的中间分部识别使用了桌面 JDK 支持、旧版 ICU 不支持的 IsHan 属性别名。
使用 Unicode 官方 ICU 60.2 原生库复现旧规则编译失败；Android 官方版本表列出 Android 9 使用 ICU 60.2。
替换为显式 CJK 字符范围，直接从编译后的核心提取规则，在 ICU 60.2 中核对规则编译、序号 1～5 和括号季号匹配。
参考：https://developer.android.com/guide/topics/resources/internationalization

搜索工作线程和 Android 桥接补充 LinkageError 错误处理；关闭时排队任务不会把线程池拒绝执行异常抛出。
对 rc5 注入初始化错误、缺失类、缺失方法时可复现未捕获线程错误，新版本同样注入时为零；
另完成 30 次启动/关闭搜索竞争检查，未发生未捕获异常。
这些检查使用电脑和同版 ICU 库，不冒充 Android 真机或模拟器运行。

不同来源同 ID 的简称不再覆盖包含季号的完整片名，避免已找到的第一部又从同系列栏中消失。
设置中的最近提示会保留异常类型及少量代码位置，不保存请求地址、Cookie、账号值或异常消息。
确有其他未处理异常时保留本地诊断后继续交给系统异常处理，不吞掉虚拟机致命错误。

## 本次真实搜索复测与修正

按用户最新要求，在电脑 JVM 中运行与 APK 相同的 TvSearch.java 和内容核心，实际请求搜索元数据接口。
每个关键词使用独立空缓存、空收藏和空历史，不登录账号，不执行设备注册或视频请求。
“车粉人”和“车粉人狠”两次均返回并归组第 1～5 部，顺序为 1、2、3、4、5。

实测发现该系列将分部数字写在剧名中间，旧版只识别末尾季号，导致各部被分成不同系列。
新增中间阿拉伯分部序号识别，同时排除常见年份、年龄和数量单位，并保留尾部与括号季号支持。
该规则不包含写死的剧名或 ID。另检查普通数量标题不会被当作分季。
实际返回的五部数据已送入离线 UI，检查顶部五个入口均可见；封面在 UI 检查中使用占位图。

## 搜索补全与同系列选季

搜索同时读取官网结果、App 搜索和官方联想词。短关键词可通过联想词得到完整剧名，
再补搜匹配作品；已浏览、收藏或观看过的公开剧集资料也参与本机关键词匹配。
不把服务端搜索限定为客户端只能输入完整片名，也没有针对某一个剧名写死结果。

App 搜索的一组 video_data 全部读取，不再只保留第一条。对较相关的作品，后台读取相关作品中的同系列续季，
按归一化基名匹配、按季号排列，在搜索结果顶部提供“同系列”快捷选季。
只显示真实返回并匹配的分季，不猜测不存在的季数；提示“已找到”而非保证已列出平台全部作品。

结果分批显示，补充时保留未提交的输入文字、当前详情与遥控器焦点。
较相关的前三页 App 结果自动补充；更多结果可继续查找，目录中间空批次不再被当作搜索结束。
界面只轮询本机搜索快照；网络工作由独立取消域和有界工作池承担，换关键词、离开界面或进入播放时取消旧请求。
每次搜索最多显示 240 条，公共剧集索引在内存中最多保存 1200 条；宽泛关键词可通过补充文字缩小范围。
这两处只保存剧集元数据，不产生离线视频文件。

## 自动选择可播放清晰度

自动模式优先选用接口声明的最高兼容清晰度。手动选择时以指定档位为上限，旧版已废弃的 `quality` 配置继续忽略。
播放器报错后保留播放位置，自动尝试下一档，
例如 1080P → 720P → 480P。资源没有某一档时跳过，正常播放后停止降档。
下一集的媒体预加载失败也会提前降档；同一播放器队列继续用于正常连播。
失败资源以内部指纹排除，避免兜底接口重新选中相同资源；尝试次数有上限，
缓冲长时间无进展或无法显示首帧时也会尝试降档。失败信息不记录地址、密钥或账号凭据。
降档按本次播放的分集保存，不把整部剧或其他剧永久限制到低清晰度。
设置页的开源许可入口按名称定位，删除第一项后不会移到错误的卡片中。

## 账号自动合并

收藏、观看历史和续播进度共用一份按账号隔离的本机资料。首次验证登录后，
自动合并未登录时保存的记录；以后进入应用、回到前台、收藏操作和播放进度变化时自动同步。
前台定期读取云端，避免只有本机上传、手机的新记录却进不了电视。

- 收藏合并去重。取消收藏、清空历史保存删除标记，防止旧响应恢复已经删除的内容。
- 进度按最近一次实际观看的时间判断，允许重看前面的集数，不以最大集号覆盖重看进度。
  暂停和退出时不把不变的旧位置重新标成“刚刚观看”；上传使用捕获进度时的时间。
- 同时修改而无法分清先后时，删除优先；能确认发生在删除之后的新收藏/观看可以重新出现。
  平台不给可靠时间时，保留删除标记，避免误恢复。
- 按已验证的账号 ID 保存记录；会话更新后仍能关联同一账号。不同账号的资料、待同步修改
  和删除标记分别保留；退出账号取消旧请求，再次登录该账号恢复原来的资料。
- 写入前先读取、三方合并。写入后回读确认，以本机修改版本防止旧请求覆盖新操作。
  网络中断保留本机资料，采用有间隔的自动重试；关闭自动合并也保留待处理修改。
- 缺失字段、空响应和接口错误不作为空书架；云端只返回最近 50 条时保留未返回的旧历史。
  缺少封面或剧名不作为删除依据，已有元数据保留。
- 账号页显示合并状态、待同步数量、最近读取时间、累计冲突处理数、部分列表提示与立即合并入口。
  收藏/历史分页显示，合并后自动刷新并保留遥控器焦点、滚动位置和详情选集页。

升级时迁移旧版本的本机记录和当前会话待同步项。账号凭据继续由 Android Keystore 加密保存。
清空已登录账号的历史时，界面明确提示该删除会在自动合并开启后同步到红果账号。

## 已有功能和范围

榜单、分类、搜索、选集、Media3 原生播放、收藏与续播、扫码/短信官网登录、评论读取和弹幕显示。
评论发布、点赞、评论删除不做；自动更新和离线视频下载按用户要求不做，没有对应入口、服务或权限。

连播保留当前与后续最多 15 集的批量模型请求和按会话隔离的缓存。
当前播放器建立后立即准备下一集，由 Media3 DefaultPreloadManager 在内存加载下一集前 8 秒，
将同一媒体源加入同一播放器队列，自动换集不主动显示控制栏或进度条。
播放器样本缓冲目标 16 MiB，不包含 WebView、解码器等总内存。
真实播放接口和电视解码表现未在线验证，不据此承诺所有网络条件下均无停顿。

## 构建

需要 JDK 17、Android SDK Platform 35、Build Tools 35.0.0、Gradle 8.9。
app/libs 含已编译的内容核心和依赖，对应 Kotlin 源码在 vendor/hgtv。
设置 JAVA_HOME 与 ANDROID_HOME，运行 powershell -ExecutionPolicy Bypass -File build-local.ps1。
产物位于 app/build/outputs/apk/debug/app-debug.apk。
在 Windows 上，若项目路径含中文并遇到 Android 构建工具的路径错误，可从纯英文的临时路径构建。

持续覆盖安装使用工作目录 signing/ 中保留的同一签名。源码包不含私钥；
自行生成的签名不能覆盖安装到原签名的应用上。

重新编译核心：Kotlin 1.9.24，JVM 1.8，编译 vendor/hgtv/android/core/src/main/kotlin 全部 .kt；
类路径为 app/libs 的依赖（排除 hgtv-core.jar）加 org.json:json:20240303。
可使用 rebuild-core.ps1 -KotlinCompilerClasspath <编译器类路径> -JsonJar <JSON JAR>。
标准 Android APK 使用系统 org.json，不打包额外 JSON JAR。

## rc15 交付检查范围

本轮遵循用户只检查 UI 再交付的范围，不运行播放、注册、登录、同步功能测试，
也不重复真实搜索请求和历史 JVM 检查。源码编译、Android Lint 与签名打包检查随构建执行。
上文的真实搜索、异常注入和旧版 ICU 检查是 rc6 的历史验证结果，并非本轮重新执行。
本轮 UI 样例覆盖部分关键词搜索的展示、同系列快捷选季、异步补充时的输入与焦点保留、空批次继续查找，
以及清晰度选项、保存后的焦点、许可入口、账号合并状态、列表刷新、焦点和滚动保留、
详情选集页保留、清空历史提示，以及既有页面和旧 CSS 兼容布局。
浏览器 UI 检查拦截外部请求，使用本地样例及 rc6 保存的公开搜索快照；检查文件不会打入 APK。

APK 做必要的封装检查：版本、包名、电视启动入口、签名、旧版签名一致性和 ZIP 对齐。
真实调用仅限搜索、联想和相关作品元数据；未调用设备注册、官网登录、云端写入、弹幕评论或播放/CDN 接口；未在电视/模拟器运行。
历史 check-offline.ps1 脚本随源码保留，未在本轮执行，不代表覆盖新版自动合并。
